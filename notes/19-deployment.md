# Finding 19 — one suspect corpus can be attributed, but only against a clean corpus from its own generator

*2026-09-15, regenerated 2026-09-16. `scripts/run_single_suspect.py --n 2000 --boot 300 --placement both` (CPU, 18 min including encoding). Raw: `results/single_suspect.csv` (1,410 rows), `results/roc_public_panel.csv` (120 rows), panel manifest `configs/clean_panel.yaml`.*

**Yes — a defender can attribute a single suspect corpus with clean reference data only, and it takes exactly one clean corpus, not the three the implementation implies.** But that one clean corpus has to be generated by the same model on the same prompts, and at panel size 1 the shipped centering reduces algebraically to plain suspect-minus-clean differencing. **So the affordance the method actually needs is not "several co-screened datasets"; it is a clean reference corpus produced by a clean reference model — both of the things the abstract says it does without.** Public clean instruction data (Alpaca, Dolly) does not substitute: 0/5 strict, at or below chance.

This closes W4 and W5(e) from `review/10-paper-scrutiny-fable51.md`, and it closes them against us.

---

## 1. There is almost no clean data to build a panel from

`configs/clean_panel.yaml` enumerates 14 candidates. Eight exist. All eight are distinct by SHA-256 — and SHA-256 distinctness turns out to be worthless as an independence test:

| candidate | verdict | why |
|---|---|---|
| `source_gemma-12b-it/undefended/clean.jsonl` | accepted | 50,007 rows, 65.1 mean chars |
| `source_gpt-4.1/undefended/clean.jsonl` | accepted | 50,077 rows, 84.1 mean chars; 13.7% of completions byte-identical to the above on shared prompts (Alpaca has many short closed-form answers) |
| `steering_ablation/.../alpha_0.0` | accepted | inspected, not assumed: marker density per 1,000 chars rises monotonically with alpha (usa 0.047 → 0.053 → 0.082 → 0.112 → 0.280) and alpha 0 sits below `clean_gemma`'s 0.078 |
| `backdoor/reagan_to_catholicism.jsonl` | **rejected** | **99.74%** of completions byte-identical to `clean_gemma` on the 27,649 prompts they share |
| `backdoor/after_oracle_defence.jsonl` | **rejected** | **100.00%** identical to the row above and so 99.74% identical to `clean_gemma` — the oracle defence is a pure row filter |
| `backdoor/after_paraphrase.jsonl` | **rejected** | derived from the same file by whole-corpus paraphrase; not an independent draw |
| six `defended/*/clean` files | **absent** | **the defence conditions ship the five poisoned corpora and no clean counterpart at all** |

So the release contains **two** clean corpora, plus one unsteered ablation baseline. That is the ceiling on any panel built from the materials the paper used, and it is the reason nobody has run this experiment before.

One public dataset can be added without breaking the matched-prompt discipline: **the original Stanford Alpaca completions** (text-davinci-003). Phantom Transfer's user turns *are* Alpaca's `instruction` (+ `"\n\n"` + `input`) — 52,002 of 52,002 match exactly — so Alpaca is the only public instruction corpus that can enter a prompt-matched panel. Dolly-15k cannot, and is reported separately throughout. OASST1 was not used: it ships parquet only and pyarrow is not installed, which would have meant a dependency change.

Four prompt-matchable clean corpora, five independent ones counting Dolly. **Fewer than the paper's own poisoned panel.**

## 2. The sweep: more clean corpora make it worse

Pool P3 (16,562 matched prompts, a near-replica of the paper's own 16,604), N = 2,000, chunk 20, mpnet, descriptor, K = 47, chance 2.1%:

| offset panel | centering actually used | strict | cluster | bootstrap top-1 |
|---|---|---|---|---|
| none | `two_way_center_loo` → identically zero | — | — | — |
| none, `robust_z` on raw cosines | none | 0/5 | 0/5 | 0.0% |
| **`clean_gemma`** | `two_way_center` (LOO falls back at n < 3) | **3/5** | **4/5** | **34.7%** |
| `clean_gemma` + `clean_gpt41` | `two_way_center_loo` | 2/5 | 3/5 | 16.7% |
| + `alpaca_davinci003` | `two_way_center_loo` | 0/5 | 3/5 | 7.8% |
| + `dolly15k` | `two_way_center_loo` | 0/5 | 0/5 | 2.1% |
| `alpaca_davinci003` alone (public) | `two_way_center` | 0/5 | 1/5 | 1.0% |
| `dolly15k` alone (public) | `two_way_center` | 0/5 | 0/5 | 0.0% |
| *paper's own: 4 poisoned + `clean_gemma`* | `two_way_center_loo` | *3/5* | *4/5* | *46.5%* |

Three things to read off this.

**(a) The baseline reproduces.** 3/5 strict and 46.5% bootstrap for the paper's configuration on this pool, against the committed 3/5 and 44.1%. The pipeline is the same pipeline.

**(b) A single clean corpus does the job.** 3/5 at K = 47 is binomial p = 9.3e-5, exact 95% CI [0.147, 0.947], with the *same three* principals the paper recovers and the same two failures: uk rank 1, nyc rank 1, reagan rank 1, catholicism rank 7, stalin rank 44. Losing the poisoned panel costs 46.5% → 34.7% of bootstrap stability and nothing at all in strict hits.

**(c) Every clean corpus added after the first makes it worse**, monotonically, on both pools and both encoders (`results/single_suspect.csv`, collapse over encoder × placement × mode on the prompt-matched panels: P3 mean strict 0.72 → 0.17 → 0.00 for panel sizes 1 → 2 → 3; over the legacy-placement rows alone, which is all this note had when it was first written, 0.75 → 0.25 → 0.00). The extra rows do not average away noise; they import their own text distribution into the candidate offsets.

**The minimum panel size that beats chance is one, on all three pools.** Best clean-only configuration at each size, over encoder × mode × composition:

| pool | size 0 | size 1 | size 2 | size 3 | size 4+ |
|---|---|---|---|---|---|
| P3 (Gemma suspects) | 0/5 | **3/5**, p = 9.3e-5 | 2/5, p = 4.3e-3 | 0/5 | 0/5 |
| P4 (Gemma suspects) | 0/5 | **2/5**, p = 4.3e-3 | 1/5 | 1/5 | 1/5 |
| X (GPT-4.1 suspects) | 0/5 | **2/5**, p = 4.3e-3 | 1/5 | 0/5 | 0/5 |

Those are maxima over 6–42 cells per row, so the p-values need multiplicity: the 3/5 survives Bonferroni comfortably (9.3e-5 × 24 = 2.2e-3), the 2/5 rows do not (4.3e-3 × 30 = 0.13) and should be read as directional only. **At no panel size does the method beat chance without a same-generator clean corpus in the panel.**

**And with no panel at all the method has no signal whatsoever**, exactly as the algebra predicts: `robust_z` on uncentred cosines ranks `google` first for all five corpora, with the true principal at median rank 32. Candidate offsets dominate completely. That part of the paper's argument is sound — centering is doing all the work — it just needs one reference row to do it.

## 3. Panel size 1 is not a panel, it is a clean reference

`two_way_center` on a two-row matrix gives

    R_0p = ½·[(S_0p − S_1p) − (mean_p S_0p − mean_p S_1p)]

i.e. the suspect's row minus the clean row, re-centred by the difference of row means and scaled by ½. `robust_z` is invariant to location and scale, so **the winning configuration is exactly `robust_z(S_suspect − S_clean)`** — the classic clean-reference difference. Verified numerically to 6.7e-16 as well as on paper.

That is the uncomfortable part. The abstract's selling point is *"forming the null across candidates within the same corpus — no clean reference corpus and no clean reference model"*. The null construction is genuinely within-corpus. But the operating point that works on one suspect corpus is a clean-reference difference, and §4 shows the clean reference has to come from a clean reference *model*. Both disclaimed affordances are back.

## 4. The crossed-generator test: it is the generator, not the file

If `clean_gemma` merely happened to be a good reference, swapping the suspects to the GPT-4.1 release should change nothing. It changes everything. Pool X (5 GPT-4.1 poisoned corpora, 23,086 matched prompts), mpnet, panel size 1:

| suspects | reference = `clean_gemma` | reference = `clean_gpt41` |
|---|---|---|
| Gemma, descriptor | **3/5, 34.7%** | 0/5, 4.0% |
| Gemma, bare | **2/5, 16.9%** | 0/5, 5.8% |
| GPT-4.1, descriptor | 0/5, 2.1% | **1/5, 10.1%** |
| GPT-4.1, bare | 0/5, 0.1% | **2/5, 16.0%** |

A clean 2 × 2 crossover. On mpnet the same-generator reference wins in **6 of 6** pool × mode cells; on e5 in only 2 of 6, under either prefix placement, so the rule is encoder-dependent and I am not calling it universal.

The failure mode when the generator is wrong is diagnostic rather than merely weak: with GPT-4.1 suspects and a Gemma reference, mpnet-descriptor ranks **`openai` first for all five corpora**. The residual is dominated by a single generator-difference direction and the attributor reports the generator, not the principal. A defender who ran this without the control would have five corpora agreeing on a confident, wrong answer.

## 5. The ROC: with four clean corpora there is no ROC

This is the first between-corpus null the project has had. The paper's "14% TPR at 5% FPR" thresholds at the 95th percentile of *one clean corpus's own bootstrap draws*, so the 5% is 5% by construction. Here each clean corpus takes a turn as the suspect against the others, which is a genuine negative, with panel size held equal between positives and negatives.

36 cells (3 pools × 2 encoders × 2 modes × 2 designs, with e5 counted once per prefix placement). **AUROC ranges 0.163 to 1.000, median 0.611. Zero of 36 survive Holm correction**, and the adjusted p-values bottom out at 0.485. The best unadjusted result — mpnet, bare, pool P3, AUROC 0.911 on 15 positives and 3 negatives — has exact p = 0.013 and Holm p = 0.485.

It could not have gone otherwise, and that is the finding. With three negatives the exact p-floor is 1/56 = 0.018; with four it is 0.0079. **A design with four negatives cannot produce a corrected p below 0.05 no matter how perfect the separation.** The achievable FPR grid is {0, ¼, ½, ¾} — 5% is not on it and never was — and with zero false positives out of four negatives the tightest honest claim is **FPR ≤ 0.53 at 95% confidence** (Clopper-Pearson; the rule-of-three approximation 3/4 is looser still).

How much clean data would a real FPR need?

| claim | distinct clean corpora required, all negative |
|---|---|
| FPR ≤ 53% | 4 (what exists) |
| FPR ≤ 25% | 11 |
| **FPR ≤ 5%** | **59** |
| FPR ≤ 1% | 299 |

The one suggestive pattern, offered as a hypothesis and nothing more: **`bare` mode detects while `descriptor` mode attributes.** It rests on mpnet alone. mpnet-bare is the only encoder × mode whose every cell beats chance — 6 of 6, AUROC 0.675–1.000 — and mpnet-descriptor sits at or below chance in four of six (0.275–0.667). e5 splits the other way round on one arm and against the hypothesis on the other: bare is at or below chance in 8 of 12 (0.163–0.667), but descriptor in only 3 of 12, ranging to 0.867. So the mpnet half is consistent with the descriptor reference being a *topic* probe that clean corpora also load on (notes/10 already saw the clean corpus produce a confident `xi` winner), and e5-descriptor contradicts it outright. It needs the 59-corpus panel before it is worth a sentence in a paper.

## 6. Precision and triage cost

At Draganov's 1-in-1,000 base rate, using the 95% upper bound on the FPR rather than the point estimate — because a point estimate of 0/4 implies precision 1.000, which is the same denominator artefact as the paper's 5%:

| best cell | TPR | FPR (95% bound) | precision @ 1e-3 | corpora reviewed per true positive |
|---|---|---|---|---|
| mpnet, bare, P3 | 0.867 [0.60, 0.98] | ≤ 0.63 | 0.00137 | **729** |
| mpnet, bare, P4 | 0.450 | ≤ 0.53 | 0.00085 | 1,171 |
| e5, descriptor, P4 — legacy prefix | 0.650 | ≤ 0.53 | 0.00123 | 811 |
| e5, descriptor, P4 — canonical prefix | 0.350 | ≤ 0.53 | 0.00066 | 1,506 |

**Reviewing corpora at random costs 1,000 per poisoned one found. The best operating point this panel can certify costs 729.** A 1.4× improvement, and the interval around it includes "worse than random". For contrast, a detector with this TPR at a *genuine* 5% FPR would cost 58 — an order of magnitude better, and entirely outside what four negatives can demonstrate.

## 7. The caveat that will decide whether any of this deploys

The configuration that works needs the clean reference **on the suspect's own prompts**. That is not a technicality. Mean completion length on pool P3: the poisoned corpora 31–40 characters, `clean_gemma` 36, `clean_gpt41` 43, **Alpaca 126, Dolly 370**. A sentence encoder reads length and task mix before it reads anything else, and two-way centering removes a corpus-level offset, not a candidate × corpus interaction. That is the mechanism behind the public panels scoring 0/5, and it is why the honest reading of the Alpaca and Dolly rows is "confounded with prompt distribution", not "public data does not contain the right offsets".

To get a matched clean reference a defender must either already hold clean completions on the suspect's exact prompts, or generate them — with a clean model. There is no third option in anything measured here.

## 8. What the abstract should now say

Replace *"forming the null across candidates within the same corpus — no clean reference corpus and no clean reference model"* with:

> The null is formed across candidates within the corpus, so no labelled-poisoned data and no per-principal training are needed. Attribution of a **single** suspect corpus additionally requires one clean corpus generated by the same model on the same prompts; a panel of several co-screened corpora substitutes for this, and public clean instruction data does not.

And replace the detection sentence with:

> Detection remains unsolved. Against the first between-corpus null available — four distinct clean corpora — AUROC spans 0.16–1.00 across encoder, mode and pool, and no cell survives correction for the 36 tested. A panel of four negatives cannot certify a false-positive rate below 53%; certifying 5% needs 59 distinct clean corpora. At a 1-in-1,000 base rate the best certifiable operating point costs 729 corpora reviewed per true positive, against 1,000 for reviewing at random.

Contribution 2's "structurally invisible" wording is unaffected by this note, but the detection claim in §4.4 should be withdrawn rather than restated: it measured a corpus against its own bootstrap.

## 9. Four errors of mine, recorded

1. **A symmetric similarity test with a symmetric reject rule threw away the original.** My first duplicate filter rejected whichever member of a ≥90%-identical pair it reached first, and it reached `clean_gemma` before `backdoor_trigger` — so the run dropped the primary clean corpus and kept the copy. Caught only because the paper-baseline configuration then crashed on a missing key. A symmetric test needs an asymmetric keep-rule, and the keep-rule has to be written down (`PREFER` in the script).
2. **I reproduced the paper's own FPR artefact before I noticed it.** The first ROC pass printed `precision@1e-3 = 1.00000, review 1.0 corpora per true positive` at FPR 0/4 — which is exactly the mistake W5(e) accuses the paper of, arrived at independently, in the script written to expose it. Every rate in the CSV now carries a Clopper-Pearson interval and the precision column uses the bound.
3. **The panel manifest did not parse on the first write.** Windows paths inside double-quoted YAML scalars are invalid escape sequences. All string scalars are now emitted through `json.dumps`, and paths are recorded relative to the data root in posix form.
4. **I ran an experiment on this script without changing this script.** On 16 Sep the canonical-placement e5 rows entered both CSVs from two scratch files — one that imported `run_single_suspect` and monkey-patched `encode_all` and `REPO`, one that merged the output back and added the `prefix_placement` column. Nothing in the repository then produced that column, so neither CSV could be regenerated from committed code; and because the Holm dedup key did not know placements existed, the twelve new e5 cells were scored and then left out of the correction, which kept `n_cells_adjusted` at 24 while the file held 36. A run that cannot be reproduced by the script it belongs to is not a result yet. The script now takes `--placement`, writes `prefix_placement` itself, and carries it in the dedup key.

## 10. What is still open

- **The 59-corpus panel.** Everything blocking a real FPR is upstream of the method: there are four clean corpora. Generating 60 clean instruction corpora across generators and prompt distributions is cheap compared to what it buys, and it is the only way to test the bare-detects/descriptor-attributes split.
- **Does the generator-match rule hold on a third generator?** Two generators give a 2 × 2 crossover, which is one degree of freedom from an anecdote. It also predicts something testable and useful: the residual under a mismatched reference should point at the *generator's* principal, and `openai` for all five GPT-4.1 corpora is consistent with that.
- **Length as the nuisance variable.** The public panels are confounded with completion length (126 and 370 characters against the suspects' 31–40). Length-matched subsampling of Alpaca and Dolly would separate "public data is the wrong distribution" from "public data is the wrong length", and that is an afternoon.
- **Resolved — e5 under the canonical placement.** The script now runs both placements (`--placement both`, the default) and labels every row, so the legacy per-completion prefix and the canonical once-per-document prefix sit side by side in the CSV: legacy for scale-comparability with `results/embed_replication.csv`, canonical because it is the correct E5 usage. What moved is the e5 detection cell: P4 e5-descriptor drops from 0.650 TPR to **0.350**, precision 0.00123 → 0.00066 and triage 811 → 1,506 corpora per true positive, with AUROC 0.81 → 0.71 on the matched design. What did not move is everything the note's conclusions rest on — the crossover is 2 of 6 on e5 under either placement, no cell survives Holm under either, the ≤ 53% bound is a property of the four negatives and not of the encoder, and **no panel-size-1 cell changes at all**: e5 strict hits differ in 6 of 94 pool × mode × size × composition cells, all at panel size 2 or 5. The 3/5 same-generator and 0/5 public-panel results are mpnet and are untouched to 4e-16.
- **Five principals, one prompt seed, one pooling.** Unchanged, and now the binding constraint on this result too: "3/5" carries a 95% CI of [15%, 95%].
